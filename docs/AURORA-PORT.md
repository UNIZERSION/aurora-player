# Aurora native port 1.3.7

## Current 1.3.7 artwork integration

The supplied MP3 exposed a real decoder compatibility failure: its APIC type 0 contains a baseline JPEG with all three sampling factors `0x12`, rejected by the former TJpgDec. A private JPEG-only stb_image fallback handles this layout and progressive scans. Private upstream TJpgDec provides genuine 1/2, 1/4 and 1/8 scaling on its supported baseline path; the shorter decoded edge remains at least 312 pixels. The output contract is still a centered 312 × 312 RGB565 image, and the loader/free API is compatible. Both libraries retain their licenses, use private symbols and leave managed dependencies unchanged. The unused LVGL automatic TJpgDec decoder is disabled.

ID3 PIC/APIC candidates are inspected and ranked before decoding: front, Other, back/leaflet/media, remaining pictures, icons last. Ordinary tags, WAV chunks and FLAC metadata use bounded seeks rather than reading padding or audio. Global v2.2/v2.3 unsync retains a bounded whole-tag compatibility path. The complete format/limit matrix, JPEG scratch budget, cancellation behavior and test commands are in [ARTWORK-1.3.7.md](ARTWORK-1.3.7.md). MP4/M4A atom support is not claimed.

The worker shares four immutable decoded covers through reference counting, avoiding full-image clones and SD validation on RAM hits. A 32-entry negative cache expires after 30 seconds. Up to eight 56 × 56 visible thumbnails are scheduled after 180 ms viewport stability; a new main-cover request cancels superseded background loading. Audio I/O gating and stop acknowledgment after file closure remain intact. Explicit library refresh/stop clears caches.

The format selector now has All, MP3, WAV, FLAC and AAC in two rows; the caption below the filters is removed. Approved shell and dragon content is preserved. The decoder host suite passed 40 fixtures, 40 cancellation boundaries, 128 truncated JPEG cases and independent Pillow pixel comparisons, including the actual user MP3. This section does not assert a firmware build result, physical installation or device load-time improvement; those require separate release evidence.

Only the control atlas switches from APK1 packets to APZ1: an exact 32-bit raw length and one checksum-protected zlib stream. Its packed size falls from 622,343 to 270,946 bytes, saving 351,397 bytes; all 1,088,192 decoded bytes are identical. Shell and dragon remain APK1. ESP32-P4 uses the IDF 5.5.2 ROM `tinfl_decompress` implementation with a 10,992-byte temporary heap state. It is freed before allocating the dragon cache, and no decompression runs during rendering. The wrapper checks the exact input/output lengths and Adler checksum and rejects truncated/trailing data; `HAS_MORE_INPUT` prevents legacy tinfl from filling truncated input with implicit zeros. Allocation or decode failure follows the existing graphics initialization error path. The host-only miniz v1.14 subset retains its public-domain license. It tests the same interface and wrapper, not an extracted copy of ROM. Device boot timing is not inferred from host timing; see [ARTWORK-1.3.7.md](ARTWORK-1.3.7.md#lossless-control-atlas-packing).

## Previous 1.3.6 integration

Opaque external dialogs are children of lv_screen_active, allowing the LVGL 9.3 cover search to prune the player behind them. Geometry, input handling and appearance are retained. Folder rows use a 1592-byte aligned stride for the same 795 visible RGB565 pixels; the eleven-row cache grows by only 1144 bytes. Background drawing excludes areas that row images overwrite. CONFIG_LIBC_OPTIMIZED_MISALIGNED_ACCESS is enabled. DPI publication synchronizes the dirty native Y range while publishing the complete framebuffer.

The current PPA presenter performs transfers and publication in a dedicated worker. It copies the flush area/last metadata, retains LVGL's source buffer until completion, and publishes only a complete frame. Three native framebuffers, dirty repair and two-VSYNC retirement protect scanout. Pending work is drained for screen sleep, wake and screenshots. The worker does not acquire the LVGL lock, avoiding a controller-lock/drain cycle. Wake renders and drains a complete frame before restoring brightness; a latched presentation failure leaves refresh paused and the backlight off. Five host scenarios exercise 80 delayed transfers, two full-screen refreshes and all 921600 pixels. These tests simulate transport timing and errors, not physical display electrical behavior. No firmware artwork or animation pixels were changed.

Physical measurements of the intermediate synchronous presenter improved from approximately 165 to 51 ms and from 5.5 to 14–15 updates/s. With asynchronous presentation, the author confirmed smoother folder scrolling. The new PERF measurement excludes the last asynchronous transfer; its logged 34 ms is not a full-frame latency and cannot establish a final FPS improvement. Gestures in that log are sparse. Candidate-specific evidence is not published.

Power off now clears retained RTC interrupt enables/flags at startup and again before cutoff. A Launcher alarm had held the shared E_TRG line active. The official [UserDemo clearRtcIrq startup step](https://github.com/m5stack/M5Tab5-UserDemo/blob/main/platforms/tab5/main/hal/hal_esp32.cpp) performs the same required cleanup. Clock/calendar/calibration and VLF are preserved. The request follows UserDemo's maximum three HIGH 100 ms / LOW 100 ms cycles with actual register readbacks. The author confirmed UI cutoff and the LED going out after the RTC correction, then normal Aurora startup with a short button press. The physical log stops after two cycles. Earlier button-induced black-screen behavior was download mode, not verified shutdown.

Shutdown still stops audio/artwork, saves the original playback state and closes SD before cutoff. If any stage fails, restore_shutdown_error retains the message, creates the dialog once under the LVGL lock and retries screen restoration every 500 ms. The shutdown loop services pending restoration even while normal screen-power service is bypassed. It never repeats hardware cutoff automatically. An explicit retry preserves the original save state and handles an already unmounted card. Extracted production methods are host-tested with HAL/filesystem failures; this is separate from physical power confirmation.

HAL startup recovery is bounded to three attempts with 50/100 ms delays and at most one bus reset before BSP display/LVGL creation. A missing expander handle is checked. Six host fault scenarios, the five presenter scenarios and the build pass. This addresses transient initialization failures observed on the device; no physical bus fault was forced, and the disturbance's root cause is not established.

APK1 packet boundaries are optimized offline using linear-time dynamic programming. The decoder and every decoded source byte remain unchanged. The 36,559-byte saving also keeps this update inside the measured 0x640000-byte M5Launcher slot; never infer another device's partition layout from this observation.

FX now crossfade two live filter voices over 10 ms. Bass+ retains the RBJ low shelf and adds a stereo-linked sample-peak hold/release gain controller rather than sample waveshaping. Retro uses bounded low-pass stages without intentional 10-bit quantization. Normal is bit-exact after transition. FX state is 18,612 bytes, allocated once, and not allocated inside the processing loop. The peak controller is not a lookahead/true-peak limiter. See validation for generated-signal measurements and hardware limits.

FFT uses the channel with greater window energy and 25% selection hysteresis instead of averaging L+R, so opposite-phase stereo no longer cancels the display. It still runs one FFT and uses approximately 1 KiB more RAM. This is a dominant-channel visualization, not a complete stereo power spectrum. The audio output is unchanged. Existing artwork caching retains four decoded covers in RAM; the recorded 3643 ms cold request includes gating, reads, decoding and scheduling. No new cold-cover decoder or quality change was made in this release.

## Previous 1.3.5 changes

These supersede all historical screen-idle, folder-rendering and particle notes below. The approved HTML/assets remain byte-identical.

Idle mode: backlight PWM duty is zero, LVGL refresh timer is paused, UI timers and audio FFT are suspended. The touch timer remains at 16 ms, panel/touch power and hardware VSYNC stay active. No DCS Display Off or Sleep In is sent. Main controller skips hidden UI updates and new artwork work. On touch, consume the complete gesture; resume refresh and render a complete player frame before restoring saved brightness. If brightness fails, preserve asleep state and pause refresh for a retry. Inactivity choices are unchanged, renamed Screen off after; new configurations default to 30 s, persisted preferences are preserved.

Folder rendering: eleven row snapshots (RGB565, roughly 0.9 MB) are reused modulo eleven. LVGL renders each caption when the row changes, then scrolls its cached image. No transformed layers or disk cache; ordinary labels remain available if snapshot allocation fails. Drop image references and caches before freeing on dialog close. Initial selection skips generating the first eleven rows if the requested folder is distant.

Framebuffer repair: subtract only the NEXT exact rotation rectangle from each stale bounding rectangle, copying at most four uncovered pieces. Never infer write coverage from merged damage boxes. For repeated 808x460 viewport frames, repair copies become zero after warm-up, versus 371680 pixels/frame before. The native PPA rotation still writes all viewport pixels. Two-VSYNC retirement remains; no writes to scanning framebuffers. Random overlap/disjoint tests compare every published pixel with a separate reference frame.

Particles: three continuous colored ribbons (44 points each), fixed frequency-to-horizontal mapping, smoothly evolving phase. Interpolated FFT energy drives spread/point radius/glow, bass drives the shared pulse. Attack 75 ms, release 220 ms; bass 115/270 ms. Positions/radii are fractional and soft-edged. No random point relocation. Exponential coefficients are calculated once per frame. Timers remain 33 ms targets; this is not a measured device frame rate.

Source references checked: [M5Stack touch polling](https://raw.githubusercontent.com/m5stack/M5GFX/master/src/lgfx/v1/platforms/esp32p4/Touch_ST7123.inl), [BSP display/backlight implementation](https://github.com/espressif/esp-bsp/blob/master/bsp/m5stack_tab5/src/bsp_display.c), [LVGL scrolling](https://lvgl.io/docs/open/9.3/details/common-widget-features/scrolling.html). Implementation was also checked against pinned local BSP 1.3.2, LVGL 9.3 snapshot code and IDF 5.5.2 PPA source. No managed dependency was edited.

## Historical 1.3.4 changes

A video recorded on the author's device showed folder and track-list interaction. These historical notes record 1.3.4; current 1.3.5/1.3.6 sections above supersede their screen, presentation and power-off behavior. The approved HTML remains unchanged.

Touch uses the existing BSP coordinate transform with a single LVGL TIMER reader every 16 ms; the IRQ reader is unregistered. No second consumer drains touch reports. Screensaver uses an opaque black LVGL top layer with a moving label and 10% backlight, keeping DCS, refresh, VSYNC and touch power running normally. Main UI decoration and FFT pause; the screen wake flag consumes the complete first gesture until release. The logo updates once per second. This is a software screensaver, not panel or system sleep.

The three native DPI framebuffers and two-VSYNC reuse fences are unchanged. Partial LVGL buffers grow from 1280×120 to 1280×480 (additional 1,843,200 bytes of PSRAM). A folder viewport can render in fewer strips and therefore invoke fewer rotated extended-window cache operations in IDF PPA. Playlist rows now recycle modulo eight; folder rows already recycle modulo eleven. Unchanged rows retain labels, textures and positions. No measured hardware FPS claim is made.

Flight separates the wing surface from the original RGBA source using the red seam in a reference photo: normalized A=(0.515,0.445), B=(0.805,0.650). Projection uses the source aspect ratio, analytic inverse coordinates, span compression 1−0.42×stroke and a small 0.055×stroke sweep along the hinge. The body is fixed. The other cut crosses transparent space between the neck and wing. Premultiplied sampling preserves coverage at the cut and composites folded overlap. No broad displacement mask bends the wing tip or the tail. Living keeps the previous inverse deformation; Flight still has 60 frames/1.65 s and Living 100/4 s. Optional --flight-only reuses a complete existing Living sequence byte-for-byte.

Particles retain fixed golden-angle positions. Music changes radial scale, subpixel disk radius and intensity through time-based envelopes (roughly 105–115 ms rise / 240–270 ms decay). Bass no longer changes particle angle. Antialiased disks avoid integer rounding jumps. The normal spectrum and waveform data path remains unchanged.

Power-off still closes playback/artwork and saves/unmounts SD before issuing the board command. M5Unified leaves its tenth 50 ms phase HIGH; Aurora now retains that HIGH for a two-second controller window before reporting a failure. The power output has no internal pull. The exact physical reason for the user's failed cutoff is not proven without measurement, and host tests do not confirm hardware shutdown. No deep-sleep fallback conceals a failed cutoff.

The keyboard default BOTTOM_MID anchor caused set_pos(12,217) to place most of it below the dialog. search_keyboard.h explicitly uses TOP_LEFT, 795×302 at (12,217), with symbol-capable 18 px font. Actual LVGL pointer tests verify bounds, several rows, space and backspace. SEARCH/CLEAR/CLOSE and keyboard ready/cancel remain functional.

Primary references: [M5Unified power-off sequence](https://raw.githubusercontent.com/m5stack/M5Unified/master/src/utility/Power_Class.inl), [M5GFX ST7123 polling implementation](https://raw.githubusercontent.com/m5stack/M5GFX/master/src/lgfx/v1/platforms/esp32p4/Touch_ST7123.inl). PPA extended-window cache behavior was inspected in the pinned ESP-IDF 5.5.2 ppa_srm.c; keyboard anchoring and input timers in pinned LVGL 9.3.0. Tests are in `tests/`; physical checks were limited to the author's device.

## Reference contract

No replacement artwork, icon set, or alternate layout was authored. ## Graphics and interaction

main/ui_shell.rgb565 is the original HTML chrome captured losslessly and quantized to the RGB565 LCD format. aurora_geometry.h is exported DOM geometry. aurora_controls.bin contains four states per control: idle off/on and pressed off/on. Pressed states use the template's translateY(1px) and brightness(1.25), including its actual icons, border and shadow. State sprites are persistent and cached in PSRAM; changed regions are invalidated rather than the whole screen.

The knob's actual inner texture rotates; the iridescent outer ring stays fixed. Its pointer uses -135 + volume×2.7 degrees from vertical. Vertical dragging changes one volume unit per original logical pixel, and a tap sets its angle, exactly following player.js. Playlist mini bars use 0.8-second alternating CSS ease-in-out and the original delay offsets. Native thumb overlays add touch dragging to the visible scrollbars.

The dragon generator derives its normalized deformation from dragon-renderer.js: nape (.555,.405), tail root (.775,.615), asymmetric 42% power/58% recovery stroke, and protected tail tip. The inverse texture map is sampled at 3× resolution with Lanczos downsampling. Flight uses 60 frames/1.65 s, Living 100/4 s, plus the same 45 degrees/second hue rotation and 0.4–1.6 speed multiplier. This is a native sampled rendition of the original motion, not a browser running on Tab5; RGB565 and finite frames mean it is not a claim of identical WebGL pixels. The 33 ms timer uses elapsed time. Animation OFF freezes frame/color; changing a setting refreshes the static pose. Audio volume never controls dragon or visualization strength.

The waveform/FFT input comes from the real engine after DSP and before output volume. Thus the drawing style matches the template but data follows music, not the HTML's simulated notes. Pause retains the last visualization. Decorative updates are skipped behind opaque dialogs and during list scrolling to prioritize touch. Asset caches use approximately 10.8 MB PSRAM; packed resources are decoded once at boot. A failed allocation reports a graphics-memory error rather than treating compressed bytes as pixels. Eight playlist rows and eleven folder rows remain fixed for up to 10,000 entries.

## Settings and transport

Gear opens the category selector directly. Dragon, Display, Audio, Library, Clock and Battery / Power share the original inline green/black controls. A back button returns to category choice. Existing RTC editing, Bluetooth pairing and text search use their functional native dialogs. No second legacy mixed settings page remains.

Repeat cycles off/all/one (storage values 0/2/1). Next/Previous preserve paused state using an atomic load-paused decoder command. Previous after three seconds restarts the current track. Off does not wrap at either end. Shuffle keeps its own history. The queue uses stable underlying track indices from the selected Files folder (including its subtree). Starting a row in Favorites instead establishes a global favorites-only playback queue, including favorites from different folders. That origin survives browsing Files/Queue, search, format filters and Shuffle changes; only successfully starting an ordinary Queue row leaves Favorites playback. Favorite membership changes refresh that queue and clear obsolete shuffle history. Removing the current favorite lets the already-playing file finish, but Next, Previous and automatic Repeat one cannot select it again; an empty favorites queue never falls back to all music. Search and format filters only affect the visible rows. Explicit row selection starts playback. Volume clears mute. Format labels/filtering never convert audio.

## Board integration

Official M5Tab5-UserDemo BSP: expander 0x43 P7 high indicates headphones; P1 controls the NS4150B speaker amplifier. Headphone insertion mutes the amplifier on the first sample; two removal samples restore it when the local route permits. Poll interval is 30 ms; HP_DET and CHG_STAT internal pulls are disabled to match the board reference. Failed detection reads fail closed and retry. Codec initialization re-applies the gate before audio is opened. Codec output remains enabled for the jack.

Official M5Unified: expander 0x44 P7 high enables charging and P6 high indicates charging. Startup configures these pins without changing quick-charge, WLAN, USB or power-off pins. INA226 current and voltage remain real readings; percent is explicitly a voltage estimate in settings. Charging can be false at full charge even with a cable attached.

Sources: https://raw.githubusercontent.com/m5stack/M5Tab5-UserDemo/main/platforms/tab5/components/m5stack_tab5/m5stack_tab5.c and https://raw.githubusercontent.com/m5stack/M5Unified/master/src/utility/Power_Class.inl .

Settings v5 imports v1–v4 (v4 tail padding is never treated as speed), SD files, favorites and Pico 0.9.0 protocol remain compatible. Hardware evidence was scoped by candidate and function; it is not a blanket certification. Pico 0.9.1 is host-tested but was not flashed to the attached module.

## 1.3.3 changes (supersede corresponding 1.3.2 details below)

Three DPI framebuffers plus two 1280×120 partial buffers. Each published predecessor is retired until two VSYNC edges after its successor publication. A third available buffer receives accumulated dirty regions from the latest completed image and can be rendered while scanout is pending. The scanout buffer is never a PPA destination. Timeout fails closed. A full history overflow becomes one full-frame dirty rectangle. Tests check all three rotations and repeated reuse. LVGL refresh period is 16 ms; actual throughput is not measured on hardware.

VisualRaster writes a 453×110 RGB565 canvas directly, then LVGL copies it once. Shared 33 ms animation timer samples current audio, avoiding cadence stalls caused by the main controller. FFT minimum interval is 16 ms; computation happens at PCM block boundaries. Peak caps and particles remain volume-independent. Modal dialogs suspend decoration. Folder rows recycle modulo 11 and retain unchanged labels.

Display Off (0x28) and backlight 0 replace Sleep In (0x10). The latter can silence the integrated ST712x touch controller. Refresh/FFT/decoration are suspended separately; touch event handling remains alive, with a 50 ms input poll during blackout. Display On (0x29) resumes, and the first gesture is consumed. DMA scanout/rails are retained. This is not whole-system sleep or removal of touch power.

Bass+ no longer multiplies its input by 0.45. It has unity mid/treble response and a +6 dB low shelf at 120 Hz. An output-only soft knee above 28000 limits peaks below 32760 without modifying recursive filter state. A 24-tap, 64-phase Blackman-windowed FIR changes turntable speed 75–125%, before local/BT routing. Precomputed Q15 tables avoid trigonometric work on the audio thread when changing the setting. Each change has a 64-frame transition; settled 100% is a bit-exact copy. Source position/duration remain in original track time. No pitch preservation is claimed. Settings v5 consumes the one padding byte of v4 and checks the old CRC before supplying a 100% default.

Artwork worker keeps four decoded RGB565 covers, owns all cache entries and returns independent image copies to LVGL. A single stat protects track identity; explicit library updates clear the cache. Cache failures safely fall back to ordinary loading. Four-millisecond yielding budget replaces a delay before every 4 KiB SD operation. Audio-buffer gating and the stop/close barrier remain in force.

Bluetooth header has only a 32-pixel-high glyph: gray for unavailable/disabled, green for available/enabled; pairing details remain in the dialog. CHG_STAT now overrides any current-derived fallback, preventing a positive/noisy current read from overriding an unplugged LOW signal. Inputs use the official M5Unified external bias, and speaker detection polls every 30 ms. Codec open re-applies the independent speaker gate.

Flight uses the original 60 phases and 1.65-second cycle, a widened hinge blend and a moved upper tip. The native generator checks positive Jacobian inside the source and an inverse residual below 2e-5 normalized units. These authorized corrections are recorded separately; the approved historical HTML reference remains unchanged.

Primary board sources consulted for these changes: [M5Unified pin/current/charge implementation](https://raw.githubusercontent.com/m5stack/M5Unified/master/src/utility/Power_Class.inl), [M5Tab5 reference headphone detector](https://raw.githubusercontent.com/m5stack/M5Tab5-UserDemo/main/platforms/tab5/components/m5stack_tab5/m5stack_tab5.c), [official Tab5 display/touch revisions](https://docs.m5stack.com/en/core/Tab5). Buffer fencing also follows the installed ESP-IDF 5.5.2 esp_lcd_panel_dpi.c DMA/VSYNC implementation.

## Historical 1.3.2 implementation notes

This section records the previous release. Its two-buffer presentation, DCS Sleep In/Out and analysis timing have been replaced by the 1.3.3 implementation above. Do not use these historical details to implement current sleep or rendering behavior.

The accepted source HTML is immutable. Only native-export.html changes the requested small captions/icon sizes. The native clock centers actual glyph bounds at y=48 (24 h and 12 h), the cover-count overlay is removed, and the battery supports a 900 ms hold. No new screenshot button is visible.

The display submits the completed backbuffer and returns flush_ready immediately. It waits for two post-publication VSYNC edges only when reclaiming the old front before the next flush, preserving the IDF DMA/VSYNC ordering guarantee. PPA copies dirty rectangles instead of CPU memcpy plus full-row writeback. VSYNC timeout still fails closed. No unsupported on_frame_buf_complete callback or vendor dependency modification is used.

Screen off sends backlight=0, Display Off (0x28), Sleep In (0x10), then pauses the LVGL refresh timer and disables invalidation. Decorative timers and FFT are paused; touch polling and audio remain active. Wake sends Sleep Out (0x11), waits 120 ms, Display On (0x29), restores brightness and refresh; the complete wake gesture is consumed. VSYNC notification is disabled while off. The IDF display transport still owns its hardware framebuffers/DMA; this is panel sleep, not ESP deep sleep or full display-rail removal. Physical ST7121/ST7123 sleep/wake behavior must be tested on hardware.

The volume disc is bilinearly sampled into a bounded RGB565 buffer once per changed value. Its original texture and outer ring are retained, without rotating an LVGL layer under a rounded clip. Volume events use an atomic latest-value mailbox. Visuals rasterize once into a 453×110 RGB565 canvas; partial refreshes reuse it. Audio analysis remains before volume/mute and after FX. Particles consume FFT bands instead of following a fixed decorative orbit. Target analysis interval: 25 ms; view data: 33 ms, without the former 66–200 ms permanent adaptive slowdown. Real frame rate remains hardware dependent.

RAM playlist preparation/old-row destruction happens outside the display lock; applying it swaps vectors and repaints only visible rows. Row widgets remain fixed (8 tracks/11 folders). Index reading uses 32 KiB stdio buffering configured before the first read, table CRC compatible with the old format, hashed duplicate detection and time-budgeted yields. Card identity, path bounds, record CRC and exact EOF are still validated. A valid cached index does not visit music directories or probe files. Scan-progress text now distinguishes loading saved data from scanning storage.

Screenshot capture copies the latest completed native framebuffer under the display lock and transposes to 1280×720. The background writer uses an exclusive filename, lossless 16-bit BMP with explicit RGB565 masks, top-down orientation, flush/fsync/close and removes incomplete writes. The display lock is not held during SD writing. Actual SD write contention still needs a device test.

The APK1 packet format stores repeated 1/2/3-byte units and literal runs with bounded lengths. tools/pack-assets.py generates the .pack files; asset_pack.h validates exact input/output lengths. Raw resources remain in source for reproducibility. The build embeds only packed shell/controls/dragon; thumbnail stays raw. No pixels, alpha samples, hue logic, frame count or playback codec are removed. Decode happens at boot only, into the same raw PSRAM layout used previously. Native tests compare every byte and reject truncated/oversized/malformed input. Host decode times are not a Tab5 startup benchmark.

## Research consulted for 1.3.2

- [Rockbox’s official database manual](https://raw.githubusercontent.com/Rockbox/rockbox/master/manual/rockbox_interface/tagcache.tex) separates loading the database into RAM from auto-update and an explicit update. This supports fast cached browsing with manual discovery of external SD changes.
- [MPD’s official user manual](https://mpd.readthedocs.io/en/stable/user.html#configuring-the-input-cache) describes bulk I/O and memory buffering to reduce disk stalls, including the contention tradeoff. Aurora keeps its existing PCM prebuffer; library I/O is now buffered as well.
- [Espressif’s LCD documentation](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-reference/peripherals/lcd/index.html) distinguishes display output control from backlight power. Both are handled explicitly here. Exact callback and sleep handling was checked against the installed ESP-IDF 5.5.2 source and pinned panel driver.
