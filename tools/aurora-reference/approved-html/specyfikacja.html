1. Co dostarczono

Otwórz tab5-player.html w aktualnej przeglądarce. Aktualny interfejs jest w całości po angielsku. Dokument zachowuje polskie opisy funkcji. Wszystkie style, skrypty, obraz referencyjny i smok są osadzone w tym jednym pliku. Nie potrzeba internetu, instalacji ani serwera. Wersja do edycji: index.html, player.css, model.js, player.js, dragon-renderer.js oraz assets/reference.png i assets/dragon.png.

Model zawiera sześć fikcyjnych utworów. „Pliki” pokazują przykładową bibliotekę, a „Karta SD” oznacza jej źródło w projekcie. Przeglądarka nie czyta karty, nie otwiera plików audio i nie korzysta z Web Audio ani Web Bluetooth. Zegar pokazuje czas Europe/Warsaw; bateria 78% jest wartością przykładową.

Granica demonstracji. Czas utworu, equalizer, FX i połączenia Bluetooth są symulowane. Ustawienia działają w pamięci bieżącej karty. Odświeżenie przywraca stan początkowy. Prototyp nie zapisuje ustawień ani ulubionych na urządzeniu.

Stan startowy: Aurora Protocol, pauza na 02:17 z 04:36, głośność 65%, Normal, widmo, kolejka wszystkich utworów; shuffle, repeat i Bluetooth wyłączone; ulubione puste. Jasność 100%, animacje włączone, zegar 24 h. Smok: Lot, tempo 1×, mieniące kolory włączone.

2. Ekran, wygląd i dotyk

Jasna, szczotkowana metalowa ramka, trzy ciemne panele, limonkowy stan aktywny i wielokolorowe widmo. Okładki korzystają z fragmentów dostarczonej grafiki, a wszystkie elementy sterujące są rzeczywistymi kontrolkami. Usunięto przyciski FLAC/AAC, ponieważ zakres prototypu obejmuje MP3/WAV.

Fizyczny ekran Tab5

Producent podaje ekran 1280 × 720. Zadane 1024 × 600 jest więc logicznym obszarem projektu, a nie natywną rozdzielczością Tab5. Źródło: M5Stack Tab5.

Dla firmware zachowującego proporcje: s = min(W / 1024, H / 600). Przy 1280 × 720: skala 1,2, obszar około 1229 × 720, margines około 26 px po każdej stronie. Transformacja dotyku: x_ui = (x_touch − 25,6) / 1,2, y_ui = y_touch / 1,2. Odrzucaj dotyk w marginesach; zaokrąglenia dobierz do sterownika. Alternatywna adaptacja do pełnej szerokości wymaga osobnego układu.

Wersja przeglądarkowa jest ograniczona do skali maksymalnej 1:1. Na mniejszych oknach zmniejsza cały panel, aby umożliwić podgląd; zmniejszony podgląd nie zachowuje fizycznych minimalnych stref dotykowych.

Wykończenie — wersja 1.5

Główny układ nadal ma 1024 × 600 px. Pod okładką siatka 72 / 110 / 72 px z odstępami 2 px daje symetryczne pola formatu i parametrów oraz wyśrodkowanego smoka. Jego wysokość rośnie z 96 do 104 px. Canvas renderuje w 220 × 208 px, aby wygładzić krawędzie przy wyświetlaniu 110 × 104 px; shader ruchu pozostaje taki sam. Nie oznacza to potwierdzonej wydajności na fizycznym Tab5.

Motto „Every second of your life is a part of your song” zachowuje monospace 7 px i odstęp liter 1,3 px. AURORA PLAYER ma 12 px, oś x = 512 px; numer wersji znajduje się po prawej. DEMO UI ma 13 px, kropka 9 px. Usunięto dodatkowy napis o braku dźwięku z belki; funkcje nadal są demonstracyjne. Znak % w baterii, głośności i jasności ma 80% wielkości cyfr.

Etykiety funkcji: FX PRESET / VISUAL DEMO (przykładowa zmiana wizualizacji), FILE FILTER / PLAYLIST (filtrowanie listy bez konwersji audio), VISUALIZER (Spectrum / Wave / Particles). Ustawienia używają nazw Living dragon / Flight, Speed, Shifting colors, Screen brightness, Interface animations, Clock format, Reset settings. Angielskie są również komunikaty, stany puste, Bluetooth i etykiety dostępności. Identyfikatory zdarzeń i modelu nie zmieniają się.

4. Model danych i zdarzenia

model.js zawiera czysty reducer reduce(state, action, rng), katalog tracks oraz selektory track i visibleTracks. Reducer zwraca kopię stanu. Funkcja losująca jest podmienialna dla powtarzalnych testów.

{
  version: 3,
  trackId: "aurora", queue: ["aurora", "midnight", "glass", "binary", "solar", "echo"],
  playing: false, position: 137, volume: 65, muted: false,
  shuffle: false, repeat: "off", shuffleBag: [], history: [],
  favorites: [],
  tab: "queue", filter: "all", fx: "normal", visualization: "spectrum",
  bt: { status: "off", device: null },
  battery: { level: 78, charging: true },
  settings: { brightness: 100, animations: true, clock24: true,
    dragon: { type: "flight", speed: 1, colors: true } }
}

Track: id, title, artist, album, duration (sekundy), format, sampleRate (Hz), bitDepth (null dla MP3), bitrate (kbps), art (prostokąt obrazu). Parametry źródłowe należą do utworu i nie wynikają z aktualnie wybranego filtra.

Inspekcja w przeglądarce

// W konsoli programisty — zwraca kopię stanu.
window.tab5Demo.getState();
window.tab5Demo.dispatch('FILTER', 'WAV');

// Zdarzenie z adaptera zasilania: piorun tylko podczas ładowania.
window.tab5Demo.dispatch('BATTERY_STATUS', { level: 78, charging: false });

// Każda akcja UI poza TICK emituje zdarzenie. Nie jest komendą audio.
document.addEventListener('tab5:action', (event) => {
  const { type, payload, state, demo } = event.detail;
  console.log(type, payload, state, demo); // demo === true
});

Timery demonstracyjne znajdują się w warstwie widoku player.js. Ręczne dispatch('BT_POWER') zmieni stan, ale nie uruchomi timera skanowania; w teście modelu należy samodzielnie wysłać BT_FOUND. Zdarzenie tab5:action nie zastępuje potwierdzenia wykonania polecenia przez sprzęt.

Wskaźnik zasilania — aktualizacja

Piorun przy baterii ma ten sam rozmiar ikony: 24 × 24 px. Jest widoczny wyłącznie dla battery.charging === true; po zakończeniu ładowania znika, pozostawiając zarezerwowane miejsce, aby belka się nie przesuwała. Tekst dostępności informuje o poziomie i ładowaniu. W demo startowo: 78%, ładowanie włączone. To wartość przykładowa, niezależna od zasilania komputera.

Akcja BATTERY_STATUS({level, charging}) aktualizuje podane pola: poziom jest ograniczony do 0–100%, a ładowanie przyjmuje boolean. Firmware powinien wysyłać faktyczny stan ładowania z adaptera zasilania, nie samą informację o podłączeniu kabla. Pełna bateria może być podłączona do zasilania bez aktywnego ładowania.

Zwiększone rozmiary tekstu: godzina 21 px, status BT 12 px, procent baterii 13 px.

5. Bluetooth: sukces, błąd i anulowanie

OFF→ Włącz →SCANNING→ około 1 s →READY→ Połącz →CONNECTING→ około 1,1 s →CONNECTED / ERROR

Studio Monitor pokazuje udane połączenie i przycisk Rozłącz. Pocket Speaker pokazuje błąd i „Ponów wyszukiwanie”. Ponowienie wraca do skanowania. Wyłączenie Bluetooth z każdego aktywnego stanu usuwa urządzenie i anuluje oczekujący timer. Spóźniony wynik po wyłączeniu nie może przywrócić połączenia.

Zamknięcie dialogu nie rozłącza urządzenia i nie zatrzymuje trwającej demonstracji. Belka zachowuje status, np. BT ON, BT DEMO lub BT BŁĄD. Przycisk w belce otwiera ten sam dialog; nie jest natychmiastowym włącznikiem radia.

Decyzja sprzętowa przed integracją audio. ESP32-C6 obsługuje Bluetooth LE, bez Bluetooth Classic. Nie należy zakładać obsługi zwykłych słuchawek A2DP na podstawie ikony Bluetooth. Połączenia w prototypie są fikcyjne. W firmware określ rolę BLE lub dobierz osobny, zweryfikowany tor audio Bluetooth; sam ekran nie dowodzi obsługi transmisji dźwięku. Źródło: Espressif, Bluetooth Overview.

6. Przeniesienie do aplikacji na Tab5

Dotyk / widgety→Intencja użytkownika→Silnik / adapter sprzętu→Potwierdzony stan→Widok

W implementacji, np. z LVGL, zachowaj model logiczny, ale zastąp syntetyczny zegar pozycją z dekodera. Play, seek, volume i FX powinny wysyłać polecenia do adaptera audio; dopiero jego zdarzenia potwierdzają stan. Pozycję seek można pokazać od razu jako podgląd, a właściwe przeskoczenie zlecić po puszczeniu palca. Do momentu potwierdzenia wyświetl krótki stan oczekiwania.

Dodatkowe stany produkcyjne — poza działającą symulacją

loading: wskaźnik oczekiwania, zablokowany seek; buffering: zatrzymanie zegara z potwierdzonej pozycji; error: czytelny powód, Ponów i Następny; empty: brak plików, transport wyłączony; no_sd: włóż kartę, zachowaj ustawienia. Przy zerowej/nieznanej długości wyłącz seek. Te stany nie są zaimplementowane jako sztuczne scenariusze audio w prototypie; trzeba je podłączyć do faktycznego silnika.

Okładki z małych miniaturek referencji służą demonstracji. Do wersji produkcyjnej przygotuj osobne grafiki odpowiedniej jakości, zamiast dekodować pełną grafikę całego urządzenia dla każdej miniatury. Nie przenoś cieni CSS ani całego runtime przeglądarki bezpośrednio do firmware.

7. Scenariusze odbioru

  1. Play uruchamia czas i animację. Pause zatrzymuje czas i wizualizację bez zerowania; dekoracyjny smok nadal zmienia barwy. Next w pauzie zmienia utwór i zachowuje pauzę.
  2. Previous po 10 s wraca do początku; naciśnięty przy 0 s wybiera poprzedni. Przy pierwszym utworze i repeat off pozostaje na pierwszym.
  3. Dotknij Glass Ocean: okładka, tytuł i format zmieniają się na WAV / 44,1 kHz / 16 bit / 1411 kbps. Rozpoczyna się demonstracja od 0.
  4. Przeciągnij seek i ustaw głośność suwakiem, pokrętłem i klawiaturą. Sprawdź synchronizację. Mute, potem unmute zachowuje poprzedni poziom.
  5. Dodaj ulubiony, sprawdź widok Ulubione, następnie usuń oznaczenie i sprawdź pusty stan.
  6. Włącz filtr WAV podczas MP3. Lista pokazuje trzy WAV; tytuł i format bieżącego utworu pozostają MP3. Sprawdź również filtr w Ulubionych. Ustawienia nie są filtrowane.
  7. Przejdź przez wszystkie FX i trzy wizualizacje. W pauzie porównaj obraz przy 100%, 0% i mute: musi być identyczny. Otwórz koło zębate, zmień jasność i format godziny; wyłącz animacje podczas play i sprawdź, że zegar utworu nadal działa. Przywróć ustawienia i wróć do Kolejki.
  8. Na Echo Chamber ustaw koniec. Repeat off kończy kolejkę, all wraca do Aurora, one powtarza Echo. Manual Next w one przechodzi dalej.
  9. Shuffle odwiedza każdy z pozostałych utworów raz. Previous wraca po historii; repeat off kończy cykl.
  10. Bluetooth: włącz, połącz Studio Monitor, rozłącz; Pocket Speaker → błąd → ponów. Wyłącz podczas łączenia: późny wynik nie zmienia OFF. Zamknij dialog klawiszem Escape.
  11. Otwórz główne ustawienia: przełącz Żywy smok / Lot, ustaw tempo 0,4× i 1,6× oraz wyłącz kolory. Zmiany od razu dotyczą smoka pod okładką. Wróć do Kolejki: układ pozostaje taki sam. Przełącz utwór: preferencje smoka są zachowane. Przewiń ustawienia i użyj resetu: wracają Lot / 1× / kolory oraz domyślne ustawienia ekranu, bez resetowania odtwarzania.
  12. Sprawdź format po lewej stronie smoka i metadane po prawej, także WAV 24 bit / 2304 kbps. Wyłącz animacje: smok ma pozostać w tym samym kolorze i położeniu. Przy 1024 × 600 nic nie wychodzi poza obudowę; ostatnie utwory są dostępne przez przewijanie. Zmniejszony podgląd zachowuje proporcje.

Automatycznie sprawdzono 27 scenariuszy czystego modelu: mutowalność, transport, granice seek/volume, repeat, shuffle, format, ulubione, FX, cykl Bluetooth, walidację ustawień smoka i ich niezależność od odtwarzania. Plik tests/model-tests.cjs w paczce można uruchomić przez node tests/model-tests.cjs. Testy modelu nie stanowią testów sterownika audio ani fizycznego panelu dotykowego.
